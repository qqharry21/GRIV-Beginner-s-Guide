一份 31 章的 GR IV 攝影入門指南，每項設定都對照官方繁體中文操作說明書並標明頁碼。
純靜態網站，無任何建置步驟、無框架、無相依套件。

## 一、部署到 GitHub Pages

### 步驟

1. 在 GitHub 建一個新的 repository（例如 `gr4-guide`），設為 **Public**。
2. 把**這個資料夾裡的所有檔案**上傳到 repo 根目錄。
   - 網頁介面：`Add file` → `Upload files` → 把檔案全選拖進去 → `Commit changes`
   - 或用指令：
     ```bash
     git init
     git add .
     git commit -m "GR IV guide"
     git branch -M main
     git remote add origin https://github.com/<你的帳號>/gr4-guide.git
     git push -u origin main
     ```
3. 進 repo 的 `Settings` → 左側 `Pages`。
4. **Source** 選 `Deploy from a branch`，**Branch** 選 `main` + `/ (root)`，按 `Save`。
5. 等 1～3 分鐘，網址會出現在同一頁：
   `https://<你的帳號>.github.io/gr4-guide/`

### 注意事項

- **所有路徑都是相對路徑**，所以放在根網域（`帳號.github.io`）或子目錄（`帳號.github.io/gr4-guide/`）都能正常運作，不需要改任何設定。
- `.nojekyll` 這個空檔案**不要刪**。它會讓 GitHub Pages 跳過 Jekyll 處理，避免底線開頭的檔案被忽略。
- Service Worker 需要 HTTPS 才能運作。GitHub Pages 預設就是 HTTPS，沒問題。
- 本機測試不能直接用 `file://` 開啟（SW 會失效），請用：
  ```bash
  python3 -m http.server 8000
  # 然後開 http://localhost:8000
  ```

## 二、PWA：安裝到裝置

部署完成後，用手機或電腦開啟網址，就能像 App 一樣安裝。

| 裝置 | 安裝方式 |
|---|---|
| **iPhone / iPad** | Safari 開啟 → 下方「分享」→ 加入主畫面 |
| **Android** | Chrome 開啟 → 右上選單 → 安裝應用程式 / 加到主畫面 |
| **桌機 Chrome / Edge** | 網址列右側的安裝圖示 |

### 離線支援

**兩個頁面都是完整離線的，沒有哪一頁需要連網。** 第一次開啟後，Service Worker 會把下列檔案存進快取，之後完全離線也能用——在山上、在飛機上、在收訊差的巷子裡都沒問題：

`index.html`（指南）、`caption.html`（EXIF 工具）、`manifest.webmanifest`、四個圖示檔，以及網站根目錄 `/`。

第一次成功快取時，畫面下方會跳出「已可離線閱讀」的提示。

EXIF 工具**本來就沒有伺服器**，所有處理都在瀏覽器內完成，所以它離線與連線的行為完全一樣。

### 快取策略

| 請求類型 | 策略 |
|---|---|
| 頁面導覽（index / caption） | **網路優先**：連線時永遠拿最新版，同時更新該頁的離線副本；斷線時用快取。快取不到的網址則退回指南首頁，不會是一片空白 |
| 同源靜態檔（圖示等） | **快取優先** |
| Google Fonts | **快取優先**，背景更新；抓不到時回一份空 CSS，讓瀏覽器立刻改用系統字型 |

導覽的快取**以各頁自己的網址為 key**。早期只有一頁時是寫死 `./index.html`，多一頁之後那樣會讓工具頁覆蓋掉指南的離線副本，離線開工具頁也會拿到指南。

### 字型是非阻擋載入的

兩個頁面的 Google Fonts 都用 `media="print" onload="this.media='all'"` 載入。這不只是效能考量——**待處理的樣式表會擋住頁尾的 inline script**，而離線正是字型抓不到的時候。如果讓它阻擋渲染，離線開啟時整頁的 JavaScript 都不會執行，PWA 的離線功能等於整個失效。改成非阻擋之後，字型抓不到就直接用系統字型，功能完全不受影響。

改這兩行時請務必保留 `media="print"` 那個寫法。

### 內容更新後的處理

改完 `index.html` 或 `caption.html` 之後，**一定要把 `sw.js` 第 4 行的版本號加一**：

```js
const VERSION = 'gr4-v6';   // 改成 'gr4-v7'
```

不改的話，使用者的瀏覽器會一直拿舊的快取版本。改了之後，使用者下次開啟會看到「有新版本」的提示，按「重新載入」即可。

## 三、全域快速搜尋

### 怎麼開啟

| 方式 | 位置 |
|---|---|
| 側邊欄的「⌕ 搜尋整本指南」按鈕 | 桌機 |
| 頂端列的 ⌕ 圖示 | 手機 |
| `⌘K` / `Ctrl+K` | 鍵盤 |
| `/` | 鍵盤 |

`↑` `↓` 選擇、`Enter` 開啟、`Esc` 關閉。點進去之後，命中的字會在內文中以綠色高亮標出並自動捲到該處。

### 搜尋的三層設計

中文沒有空白可以斷詞，所以這裡沒有用一般的分詞搜尋，而是**子字串比對加上加權評分**。索引在頁面載入時從 DOM 即時建立，所以改內容後搜尋會自動同步，不需要重新產生索引檔。

**L1 — 字面比對**

依命中位置給不同權重，決定哪一章排前面：

| 命中位置 | 權重 |
|---|---|
| 章節標題 | 10 |
| 小標題 h3 / h4 | 5 |
| 選單路徑（綠色區塊） | 4 |
| 表格內容 | 2 |
| 一般內文 | 1 |

同一段落內重複命中最多累計 3 次，避免長表格因為字多而灌水。

**L2 — 同義詞與口語別名**

新手不會搜「散景」，他會搜「背景模糊」。`SYN` 這張表把日常說法對應到手冊裡真正使用的詞，權重 0.65（低於字面命中，所以不會蓋過精準結果）：

```
背景模糊 → 景深 / 光圈 / F2.8 / 散景
太暗     → 曝光補償 / 測光 / 感光度
糊掉     → 手震 / 快門 / Shake Reduction
顏色怪   → 白平衡 / CTE / 色溫
星軌     → 間隔合成 / 長時間曝光
```

另外支援直接搜說明書頁碼：`p.58`、`p58`、`說明書58` 都會被正規化成 `p.58`，找到所有引用該頁的章節。

**L3 — 症狀直達**

打「照片太暗」不需要自己判斷該看哪一章，`SYMPTOM` 規則會直接把對應章節推到第一位，並標上綠色徽章說明原因：

```
照片太暗  → 互動診斷 + 拍壞了?診斷表 + 曝光補償   [問我兩題]
糊掉      → 互動診斷 + 拍壞了?診斷表 + 快門       [問我兩題]
該調什麼  → 互動診斷 + 該調哪一個?決策地圖        [互動診斷]
濾鏡 / 風格 → 互動診斷 + 影像控制                 [挑濾鏡]
新手      → 出片配方 + 開始這裡                   [從這裡開始]
開不了機  → 疑難排解                              [相機故障]
選單在哪  → 完整選單速查表                        [選單地圖]
```

`to` 陣列的順序就是排名：第一個得 60 分，之後每個少 12 分。所以把互動診斷放第一個，症狀類的查詢就會優先導到那一章。

### 怎麼擴充

兩張表都在 `index.html` 的 `<script>` 區塊最上方，直接改就好：

```js
var SYN = {
  '你的口語說法': ['手冊裡的詞1', '手冊裡的詞2'],
};

var SYMPTOM = [
  { q:['症狀關鍵字1','症狀關鍵字2'], to:['章節標題片段'], why:'徽章文字' },
];
```

`to` 是用**章節標題的片段**去比對，不是章節編號——所以之後增刪章節不會壞掉。

## 四、互動診斷章節（第 30 章）

最後一章「互動診斷:現在該調什麼」是全書唯一的互動章節，分兩個模組。

### 模組 A — 症狀診斷器

兩層決策樹，最多點兩下就到答案：

```
入口:  ○ 我剛拍完，照片不對        ○ 我正在現場，不知道怎麼設
         ├ 糊 / 不清楚                └→ 光線狀況 4 選 1 → 起手設定卡
         ├ 太暗 / 太亮
         ├ 顏色怪
         ├ 畫質髒
         └ 構圖沒感覺
              └ 追問一題細分 → 答案卡
```

答案卡固定五段式：**診斷 → 立刻做 → 選單路徑 → 出處頁碼 → 連到原章節**。

### 模組 B — 濾鏡風格選擇器

不從 14 個影像控制的名字裡挑，而是從「想要什麼感覺」反查（濃郁鮮豔、日系淡雅、黑白硬派⋯⋯），每張卡附官方說明原文、建議參數起手式、適合場景，以及「影像控制不套用在 RAW 上」的提醒。

### 設計原則

**這一章不產生任何新的事實主張**，只把第 05～13、21、22、26 章已標註出處的內容重新組織成互動流程，頁碼沿用原章節標註。唯一的例外是模組 B 底下的六格「方向感示意」——那是用 CSS 濾鏡做的模擬，已在頁面上明確標示為非實際成像。

### 怎麼擴充

問題與答案卡**全部是靜態 HTML**，JS 只負責切換 `hidden`。這樣搜尋索引掃得到、列印印得出來、沒有 JS 也不會是空白頁。要加一個新分支只要三步：

```html
<!-- 1. 在某一層問題裡加一個選項，data-dx-go 指向新卡片的 id -->
<button class="dxo" type="button" data-dx-go="rMyCase">我的新症狀</button>

<!-- 2. 在同一個 .dx 容器裡加對應的答案卡 -->
<div class="dxr" data-dx-card="rMyCase" tabindex="-1" role="region" hidden>
<h4>標題</h4>
<div class="row"><span class="k">立刻做</span><div class="v">…</div></div>
<!-- 3. 想連回原章節就加這個按鈕，數字是章節索引 -->
<div class="row"><span class="k">想懂為什麼</span>
  <div class="v"><button class="go" type="button" data-dx-ch="6">第 06 章</button></div></div>
</div>
```

不需要改任何 JS。`data-dx-go` 可以指向另一層問題（`data-dx-step`）或一張答案卡（`data-dx-card`），控制器會自己判斷。

## 七、EXIF 貼文產生器（`caption.html`）

一個獨立的小工具頁，從指南第 21 章「選片與整理」進入。丟一張照片進去，讀出檔案裡的 EXIF，產生一段可以直接貼到 IG 的文案。

### 隱私

**沒有伺服器，照片不會被上傳。** 讀檔、解析、產文字全部在瀏覽器內完成，關掉網路也能用。頁面上有明確說明，不是只寫在這裡。

如果照片帶 GPS 座標，工具會跳出警告提醒使用者（直接把原始檔傳給別人會連位置一起送出），而**產生的文案永遠不含座標**。

### EXIF 解析是自己寫的

沒有用 `exifr` 之類的套件，而是在 `caption.html` 裡實作了一個最小的 EXIF 讀取器（約 130 行）。理由有三個：

1. 維持整站「無框架、無相依套件」的原則
2. CDN 套件會破壞離線能力（Service Worker 快取不到跨網域資源）
3. 只需要十幾個標籤，完整套件是殺雞用牛刀

支援範圍：

| 格式 | 作法 |
|---|---|
| JPEG | 掃描 APP1（`FFE1`）區段找 `Exif\0\0`，再讀後面的 TIFF |
| DNG / TIFF | 檔頭本身就是 TIFF 標頭，直接讀 |
| 位元組序 | 大端（`MM`）小端（`II`）都支援 |
| HEIC | **不支援**（容器格式完全不同）。頁面會告訴使用者怎麼改設定或轉檔 |

讀取的標籤：機身、鏡頭、光圈、快門、ISO、焦距與等效焦距、曝光補償、測光方式、曝光模式、白平衡、閃光燈、拍攝時間、尺寸、GPS 有無。

**讀不到「影像控制」（濾鏡色調）是正常的** — 那是 Ricoh 寫在自家 MakerNote 專屬欄位裡的資料，不在標準 EXIF 中。工具不會去猜。

為了不把整張 RAW 讀進記憶體，只讀檔案的前 2MB（EXIF 一定在最前面）。

### 四種文案樣板

樣板都在 `caption.html` 的 `TPL` 物件裡，每個是一個 `function(d, o)`，`d` 是整理好的參數、`o` 是選項。要加一種樣式就在 `TPL` 加一個 key，再到 `.tabs` 加一顆對應 `data-style` 的按鈕即可。

```
標準  📷 RICOH GR IV / F5.6 · 1/250s · ISO 400 · 28mm / #ricohgr …
極簡  RICOH GR IV · F5.6 · 1/250s · ISO 400 · 28mm
詳細  分隔線 + 逐項條列（光圈/快門/感光度/焦距/曝光補償/測光/模式）
英文  RICOH GR IV | f/5.6 | 1/250s | ISO 400 | 28mm
```

可切換是否加標籤、日期、emoji，可加一句自己的話，標籤也可自訂。輸出框可直接編輯，並顯示字數（超過 IG 的 2200 字上限會提示）。

### 不做自動發文

Instagram 的官方 Graph API 只開放給 Business / Creator 帳號，且需要通過 Meta 的 App Review；個人帳號沒有合法的自動發文管道。所以這個工具做到「產生文案 + 一鍵複製」為止，發文由使用者自己貼上完成。

## 八、其他功能

- **日間 / 夜間模式**：側邊欄與頂端列的「顯示」按鈕，循環切換 `自動 → 日間 → 夜間`。「自動」跟隨系統設定。
- **RWD**：手機、平板、桌機、橫式直式都做過處理，含 iPhone 瀏海與底部安全區（safe-area）。
- **列印**：直接列印會輸出全部 31 章，每章分頁，自動隱藏側邊欄與搜尋介面。第 30 章的互動介面會自動收起，答案卡則全部展開，印出來是一份完整的平鋪對照表。
- **網址分享**：每一章都有自己的 hash（例如 `#c22`），可以直接分享到特定章節。
- **兩頁互相往返**：指南側邊欄有「EXIF 貼文產生器」按鈕，工具頁左上角有「← 回指南」。指南的按鈕會把**目前章節**帶在網址上（`caption.html?from=c21`），工具頁的返回鍵就會回到那一章，不會跳回開頭。
